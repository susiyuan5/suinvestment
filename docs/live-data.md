# 数据与页面分离

页面代码在 `main`，GitHub Pages 仍只从 `main` 发布。生成数据在 `live-data`，该分支没有网站、工作流或 Pages 环境。不要合并数据分支回 `main`。

`live-data-manifest.json` 的 `formatVersion: 1`、`dataCommit`、`codeCommit`、`publishedAt` 分别表示清单格式、不可变数据提交、生成代码提交和发布时间。浏览器每个刷新批次固定一个数据提交；显式刷新重新请求清单。实际行情时间仍由原有时效校验判断，发布时间不等于行情时间。原始文件 CDN 可能缓存，不保证秒级更新；读取失败显示错误，不使用打包旧文件冒充最新数据。

## 自动任务

`scripts/live-data-tasks.json` 保留每项任务原来的生成和校验命令及输出白名单。工作流从 `main` 取程序，公共发布器 `scripts/live_data.py` 先加载最新数据作为输入。生成失败不提交；成功建立数据提交及指向它的清单提交，一次普通 fast-forward 推送。任务发生竞争时最多尝试三次；当前实现保守地将所有生成数据视为输入，变化则重新生成、校验。

任务无权发布白名单外的代码、配置、密钥。初始快照仅选择已跟踪的生成文件；页面附带的旧数据只作为测试、离线研究及显式回滚材料，不作为线上失败兜底。手工目标配置和策略配置仍在 `main`；浏览器账本和人工持仓存储不变。

加密持仓任务只建立面向 `live-data` 的审核 PR，不自动合并。人工合并后，公共数据任务或每小时第 15/45 分钟的 `Publish reviewed encrypted holdings` 任务校验并发布；可手工运行该任务立即处理。只移动密文，解密密钥及解密操作仍留在本机。迁移前面向 `main` 的持仓 PR 不应继续合并，应使用新数据分支 PR 审核。

数据任务运行生成校验、独立数据模块测试与 `node scripts/live-data-smoke.mjs`，不运行 Pages 部署。页面提交仍运行完整测试和 Pages smoke。Actions 运行记录会继续增加，历史 deployments 不删除。

## 验证与回滚

1. 查看 `node scripts/live-data-smoke.mjs` 输出的固定提交和跨域响应。
2. 记录 `main` SHA 和 `github-pages` deployments 数量，运行 `Update weekly market data`，确认只有 `live-data` 更新。
3. 页面顶部显示数据提交及发布时间，各面板显示实际数据时间。缺失/过期仍遵循原有安全限制。
4. 如需回滚，先停用这些数据任务及审核发布任务。将页面的 `live-data.js` 数据地址配置回同源并明确使用最近已验证快照，恢复旧工作流后再恢复计划任务。回滚是一次代码部署，不能只停用任务却继续把旧快照显示成新数据。不要重置或导入任何个人账本。

迁移初始代码版本：`59e72e741c6604495f863713acac725fc418cd15`。该版本的原工作流可用 `git show <SHA>:.github/workflows/<任务>.yml` 提取恢复；恢复前检查期间新增数据并从数据分支复制最新已验证输出，避免历史回退。
